Search the Catalog for paid services, ranked by **ARD hybrid relevance** — semantic (meaning) matches merged with lexical (keyword) matches, most relevant first — falling back to pure lexical when the embedding provider is unavailable. **Discovery only — free, no credential, nothing charged.**

To have the platform **pick** (and optionally pay) the single best service for a need instead of choosing yourself, use [`route_by_intent`](/mcp/catalog-mcp/route-by-intent).

**Auth:** free · **Charges:** nothing

## Arguments

| Argument | Required | Type | Description |
| --- | --- | --- | --- |
| `query` | yes | string | What you need, in plain language (`"translate documents to German"`). Ranked semantically **and** lexically. |
| `category` | no | string | Restrict to services carrying this catalog **tag** (filters on tags exactly like `tag`). Given together with `tag`, matches a service carrying **either** one. |
| `protocol` | no | enum | One of `x402`, `mpp`, `rest`, `a2a`, `other`. Only `x402` and `mpp` are payable via the Router. |
| `tag` | no | string | Restrict to services carrying this catalog tag (a protocol or domain keyword from a listing's `tags`). |
| `prefer` | no | string | Move this opaque catalog slug to the front **when it matched the returned page**; otherwise keep the normal ranked fallback. |
| `exclude` | no | string | Never return this opaque catalog slug. |
| `pageSize` | no | integer | Page size, 1–100. |
| `detail` | no | boolean | `true` returns every listing in full, as the catalog publishes it (the ARD record, with each endpoint's request and response shapes, examples and quote), plus its `slug` (local hits). Large; to read one listing, prefer [`get_service`](/mcp/catalog-mcp/get-service). Default `false`: concise listings. |

<Warning>
**Only the first page is returned.** The `pageToken` in the result **cannot be passed back** to this tool. To see other matches, narrow the `query` or filters, or raise `pageSize` (up to 100).
</Warning>

## Returns

`results` and an opaque `pageToken` (informational only). Each result is a **concise listing**: the fields you pick a service by, flattened to one level (endpoints trimmed to two here). A hit with an `nvm:catalog` block comes from an older server, which returns the full ARD record instead (and has no `detail`): its catalog fields sit inside that block, and it has no `slug` (the slug is the last segment of `identifier`).

```json
{
  "results": [
    {
      "slug": "openweather-mpp",
      "identifier": "urn:air:api.live.nevermined.app:service:openweather-mpp",
      "displayName": "OpenWeather",
      "description": "Global weather data — current conditions, 5-day forecasts, hourly forecasts, air quality index with pollutants, geocoding, and One Call 3.0",
      "tags": ["weather", "forecast", "conditions", "temperature"],
      "matchReason": "semantic_similarity",
      "rankingSource": "semantic",
      "semanticScore": 46,
      "protocol": "mpp",
      "network": "Tempo",
      "priceLabel": "$0.005–$0.01",
      "headlinePriceLabel": "from $0.005",
      "displayPriceLabel": "$0.006",
      "displayPriceSource": "settled",
      "routerPayable": true,
      "healthStatus": "operational",
      "uptime30d": 100,
      "successRate": 100,
      "verificationStatus": "verified-by-canary",
      "endpoints": [
        { "method": "POST", "path": "/openweather/current-weather", "invokePath": "openweather/current-weather", "priceLabel": "$0.006", "description": "Current Weather" },
        { "method": "POST", "path": "/openweather/forecast-5day", "invokePath": "openweather/forecast-5day", "priceLabel": "$0.008", "description": "5-Day Forecast" }
      ]
    }
  ],
  "pageToken": "eyJvZmZzZXQiOjJ9"
}
```

What a listing carries:

- **`slug`** is what [`get_service`](/mcp/catalog-mcp/get-service), [`quote_service`](/mcp/catalog-mcp/quote-service) and [`pay_service`](/mcp/catalog-mcp/pay-service) take. Only a hit from this Catalog has one. A `rankingSource: "federated"` hit comes from another registry: it has no `slug`, carries its `url` and `source` instead, and can't be quoted or paid here.
- `identifier`, `displayName`, `description` and `tags` describe the service; `matchReason`, `rankingSource` and one score rank it.
- `protocol`, `network` and the prices: `priceLabel` (the listing's advertised price), `headlinePriceLabel` (derived from endpoint prices; "from" means they vary) and `displayPriceLabel` (the whole listing: what calls to it settled at when `displayPriceSource` is `settled`, the merchant's latest quote when `quoted`).
- Health and payability: `routerPayable`, `healthStatus`, `uptime30d`, `successRate`, `verificationStatus`, plus `freeAfterPurchasePaths`: path prefixes free to poll after your own paid call, within the follow-up window. A call under one that answers `402` is still paid; see `get_service`.
- `endpoints`, each with its `method`, `path`, `invokePath`, `priceLabel` and `description`, plus `access` or `auth` when set. For an untemplated `path`, `invokePath` is the subpath to send, and `""` means the service base already is the endpoint. A templated `path` (a `:name`, `{name}` or `*` segment) carries no `invokePath`: call `get_service` and send its `payServiceArgs.path` with each `pathParams` segment, whether a placeholder or the example's value, replaced by your own.
- **An omitted field is unknown or withheld, never defaulted:** a missing `healthStatus` doesn't mean healthy.
- Request shapes, examples and quotes are not in a concise listing. Read them with `get_service` before paying, or pass `detail: true`.

Reading the ranking:

- **Read the order, not the numbers.** Results come back in pick order.
- `rankingSource` is per-item: `semantic`, `lexical` or `federated`. `matchReason` is a closed value explaining the match.
- The score field is scale-specific (`semanticScore`, `lexicalScore` or `federatedScore`). The scales are not comparable, so don't re-sort across them.
- `displayPriceSource: "settled"` means the `displayPriceLabel` reflects real multi-payer settlement — the service is genuinely used, not just advertised.

Then read one service in full with [`get_service`](/mcp/catalog-mcp/get-service).

## Try it

**Ask your assistant:**

> Search the Nevermined catalog for weather services.

**Call it directly** (discovery is free — no credential needed):

```bash
curl -X POST https://mcp.live.nevermined.app/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search_services","arguments":{"query":"weather","pageSize":5}}}'
```
