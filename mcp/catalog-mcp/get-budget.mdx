Read the spending budget [`pay_service`](/mcp/catalog-mcp/pay-service) draws on: its cap, what's been spent, what remains, how many payments were made (and the limit, if any), and when it expires. Reading charges nothing. Use it whenever the human asks how much is left, or before a run of paid calls. Needs a credential.

**Auth:** key / grant · **Charges:** nothing

## Arguments

| Argument | Required | Type | Description |
| --- | --- | --- | --- |
| `delegationId` | no | string | A specific delegation to read (every paid `pay_service` result carries one). Omit to read the budget `pay_service` spends by default. |

## Returns

The figures are nested under `budget`; `delegationId`, `message`, and `instructions` sit alongside it. Money is in **cents**: `capCents` is whole cents; `spentCents` and `remainingCents` can carry up to four decimals (charged per call at 1/10,000 of a cent, e.g. `"1.632"` = 1.632¢):

```json
{
  "delegationId": "121b880a-…",
  "budget": {
    "capCents": "500",
    "spentCents": "8.04",
    "remainingCents": "491.96",
    "currency": "usdc",
    "transactionCount": 3,
    "maxTransactions": null,
    "expiresAt": "2026-10-02T13:29:31.691Z"
  },
  "message": "Your budget: cap 5.00 USDC, 0.08 USDC spent, 4.92 USDC remaining, valid until 2026-10-02.",
  "instructions": "Relay message as it stands; call pay_service to spend from this budget."
}
```

- **Relay `message` as it stands** — it is written to be read to the human, and because the figures include routing fees and rounding, **never substitute a figure of your own**.
- Inside `budget`: `spentCents + remainingCents = capCents` while within cap; `transactionCount` is how many payments were made and `maxTransactions` the limit (`null` when there is none).
- **`lockedInChannels`**, when present, is money the wallet this budget pays from has deposited into payment channels with merchants that charge per call over an MPP session, per token (same shape as in [`wallet_balance`](/mcp/catalog-mcp/wallet-balance)). It is **not spent** and **not charged to this budget**: it can pay further calls only to the merchant holding each channel, and what is unused comes back to that wallet when the channel closes, after 15 minutes without use; `message` then says so. It is that **wallet's total**, not a figure of this budget's own: every budget paying from the same wallet reports the same channels. An empty list means nothing is locked; `null` means it could not be read, and `message` says that too.
- With no `delegationId` this reads the budget `pay_service` would use, which only includes budgets that can still pay. So `{ "status": "no_active_delegation" }` also covers a budget that ran out or expired — pass the `delegationId` from an earlier `pay_service` result to read that one anyway.

## Nevermined credits

With a personal API key, the result also carries your [Nevermined credits](/products/catalog/router/subscription), with or without a subscription:

```json
{
  "status": "no_active_delegation",
  "message": "There is no delegation spending budget, but your Nevermined credits cover the catalog services that carry a credits tariff: pay_service uses them by default for those, and does not fall back to a delegation when they run out. To pay merchants from a delegation instead, call setup_delegation.",
  "subscription": { "subscribed": false },
  "subscriptionMessage": "You have no Nevermined Subscription. You have 2,000 credits. 2,000 welcome credits expire on 2026-11-26.",
  "credits": {
    "total": "2000",
    "spendable": "2000",
    "parts": [
      { "kind": "welcome", "credits": "2000", "expiresAt": "2026-11-26T09:12:44.000Z", "frozen": null }
    ],
    "nextExpiry": { "credits": "2000", "at": "2026-11-26T09:12:44.000Z" }
  },
  "creditsMessage": "You have 2,000 credits. 2,000 welcome credits expire on 2026-11-26."
}
```

- `credits` is your balance as [`GET /api/v1/credits/balance`](/api-reference/router/credits-balance) reports it: `spendable` is what can pay a call now, and `parts` lists the credits left by kind (`welcome` for free credits, `allowance` for a subscription's monthly allowance) and expiry, with any freeze. `creditsMessage` says the same in a sentence. Relay it as it stands.
- `subscription` is your Nevermined Subscription, with `subscriptionMessage` to relay as it stands. It's `{ "subscribed": false }` when you don't subscribe. A subscriber sees the plan, the reset date and `creditsLeft`. For a subscriber who also holds free credits, `subscriptionMessage` counts them in the credits "left this month", so relay `creditsMessage` for what each part is and when it expires:

```json
{
  "subscription": {
    "subscribed": true,
    "creditsLeft": "1240",
    "spendable": true,
    "resetsAt": "2026-10-30T00:00:00.000Z",
    "cancelAtPeriodEnd": false,
    "status": "active",
    "suspended": false,
    "plan": { "catalogId": "3f2b…", "planKey": "standard", "creditsPerCycle": "20000" }
  },
  "subscriptionMessage": "Nevermined Subscription (standard): 1240 of 20000 credits left this month; the monthly allowance resets on 2026-10-30 and unused credits do not carry over."
}
```

- **Don't count credits yourself.** `credits.spendable` is what [`pay_service`](/mcp/catalog-mcp/pay-service#pay-with-subscription-credits) can spend now with a personal API key; a call made in an organization never spends them. `subscription.creditsLeft` counts your whole balance, free credits included. `subscription.spendable` is about the subscription only: `false` unless it's `active` or `trialing` and not suspended by a card dispute. While it's overdue (`past_due` or `unpaid`), only its allowance is frozen.
- `credits` is `null` when your balance couldn't be read this time, and `creditsMessage` says so. That never means zero.
- An OAuth connection that you [allowed to spend your credits](/products/catalog/router/subscription#who-can-spend-your-credits) gets `subscription` but no `credits`: that balance takes a personal API key. Any other OAuth connection gets neither. Both are also absent when the subscription isn't available to you or when it couldn't be read this time. Absent never means zero.
- With no delegation, `status: "no_active_delegation"` still carries these fields, and drops `nextTool: "setup_delegation"` when your credits can pay: `pay_service` uses them by default. An OAuth connection gets no `credits`, so without a subscription that can pay it keeps `nextTool: "setup_delegation"`, even when `pay_service` can spend its free credits.

## Try it

**Ask your assistant:**

> How much of my spending budget is left?

**Call it directly** (charges nothing):

```bash
curl -X POST https://mcp.live.nevermined.app/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer $NVM_API_KEY" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_budget","arguments":{}}}'
```
