The **Catalog MCP** (also called the Commerce MCP) is a hosted [MCP](https://modelcontextprotocol.io) server that lets an agent in any MCP host **discover** paid services in the [Nevermined Catalog](/products/catalog/overview) and **pay** for them through the [Router](/products/catalog/router/overview) — funded by the caller's own spend-capped budget. The server holds no funds and stores no state: every payment draws on the caller's own Delegation, using the caller's own credential, forwarded per request and never stored.

This section is the **tool-by-tool reference** — one page per tool. For the narrative walkthrough (per-assistant click-paths, the consent screen, a first paid call), see the [Catalog MCP product page](/products/catalog/mcp).

<Note>
This is the **buyer** side. To put a paywall on *your own* MCP server so its tools get paid, that's the seller side — see [MCP Integration](/integrations/mcp). The [Docs MCP](/mcp/docs-mcp/overview) is a third, unrelated server that streams this documentation into your IDE.
</Note>

## Import the MCP

### Environments

| Environment | Server URL | What a payment costs |
| --- | --- | --- |
| **Live** | `https://mcp.live.nevermined.app/mcp` | Real merchants, real money — bounded by the cap you approve. |
| **Sandbox** | `https://mcp.sandbox.nevermined.app/mcp` | Testnet merchants, testnet funds — the place for a first run. |
| **Live (challenge-on-connect)** | `https://mcp.api.live.nevermined.app/mcp` | For hosts that only run OAuth when challenged on connect (e.g. LangSmith Fleet). |
| **Sandbox (challenge-on-connect)** | `https://mcp.api.sandbox.nevermined.app/mcp` | As above, on sandbox. |

### Harness or local environment (API key)

Any host that can send headers — a coding agent with a config file, a script, a local MCP client — points at the server URL and puts your Nevermined API key on the `Authorization` header:

```json
{
  "mcpServers": {
    "nevermined-catalog": {
      "url": "https://mcp.live.nevermined.app/mcp",
      "headers": { "Authorization": "Bearer ${NVM_API_KEY}" }
    }
  }
}
```

Discovery works with no key; paying needs a Nevermined **API key** and a funded, spend-capped **Delegation**. Get a key from the [Nevermined app](https://nevermined.app); see [Get an API key](/products/catalog/mcp#2-get-an-api-key). A **stdio-only** host can bridge with [`mcp-remote`](https://www.npmjs.com/package/mcp-remote).

<Warning>
The config above points at **live**, where `pay_service` moves real funds. Rehearse on sandbox first, then switch to live with a small Delegation cap and the cheapest sub-cent service.
</Warning>

### Claude, ChatGPT, LangSmith Fleet (OAuth, no key)

If your assistant runs OAuth for you, connect by **URL alone** — no API key — and approve a spending cap once. Point the assistant at the server URL, leave the client ID and secret empty, and it discovers the rest. The per-assistant click-paths (and LangSmith Fleet's manual setup) are on the [product page](/products/catalog/mcp#connect-from-your-assistant).

## Transport

Streamable HTTP, **stateless** — each call is a self-contained JSON-RPC request; no session id is required.

| Path | Method | Purpose |
| --- | --- | --- |
| `/mcp` | `POST` | The MCP endpoint — `initialize`, `tools/list`, `tools/call`. |
| `/health` | `GET` | Liveness. |
| `/ready` | `GET` | Readiness — also checks the Nevermined API is reachable. |

Send `Content-Type: application/json` and `Accept: application/json, text/event-stream`. `initialize` reports the server as `nevermined-commerce`.

## Authentication

Two ways, one server. The credential — key or grant — is forwarded to the Nevermined API **per request**, never stored, never logged, never sent to the merchant.

- **API key** — your Nevermined key on `Authorization: Bearer <key>`. Works on any header-capable host.
- **OAuth** (`commerce` scope) — connect with **no** header. When the server needs a credential it answers `401` with a `WWW-Authenticate` challenge pointing at `/.well-known/oauth-protected-resource/mcp`; your host runs the flow, you approve a spending cap once, and it retries with the grant. The grant spends only from the Delegation you approved, through the Router. See [Auth & transport](/products/catalog/mcp#auth-&-transport) for which hosts can be granted `commerce`.

**Free vs paid.** Discovery is free — no credential. Everything else needs a credential; of those, only `pay_service` and `route_by_intent` (with `autoPay: true`) move money — the rest read your account or price a call and charge nothing.

## Result and error conventions

These hold across every tool; each tool page notes only what it adds.

- **One JSON object per call.** Each tool returns a single JSON object as the MCP text content.
- **Refusals are legible results, not exceptions** — an object carrying an `error` (and often a `code` and `retryable`), so an agent can branch on it.
- **Missing or rejected credential → `401`** with a `WWW-Authenticate` challenge (`error="invalid_token"` when refused). A host that links per tool gets the challenge in-band under `_meta["mcp/www_authenticate"]`.
- **Money is in cents.** `capCents` is whole cents; `spentCents` / `remainingCents` carry up to four decimals (charged per call at 1/10,000 of a cent). The routing fee is included — never re-derive a figure by summing your own calls. Payment *amounts* in [`list_payments`](/mcp/catalog-mcp/list-payments) are in the asset's smallest unit (`assetDecimals`), not cents.
- **Error codes.** Router refusals carry `BCK.ROUTER.*` ([Router guardrails](/products/catalog/router/guardrails#every-error-code)); OAuth refusals carry `BCK.OAUTH.*`. Full catalogue: [API error reference](/development-guide/api-errors/overview).
