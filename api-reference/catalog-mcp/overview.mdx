This is the **machine-readable reference** for the [Catalog MCP](/products/catalog/mcp) — the hosted [MCP](https://modelcontextprotocol.io) server that lets an agent in any MCP host **discover** paid services in the [Nevermined Catalog](/products/catalog/overview) and **pay** for them through the [Router](/products/catalog/router/overview), funded by the caller's own spend-capped budget. Every tool, argument, return field, and refusal is documented here.

<Note>
Looking for the **guided setup** — how to connect Claude, ChatGPT, or LangSmith Fleet, approve a spending cap, and run your first paid call? That lives on the product page: [Catalog MCP](/products/catalog/mcp). This reference is the tool-by-tool contract your agent calls against.
</Note>

## Transport

The server speaks **Streamable HTTP** and is **stateless** — each call is a self-contained JSON-RPC request; no session id is established or required.

| Path | Method | Purpose |
| --- | --- | --- |
| `/mcp` | `POST` | The MCP endpoint. `initialize`, `tools/list`, and `tools/call` all `POST` here. |
| `/health` | `GET` | Liveness. |
| `/ready` | `GET` | Readiness — also checks the Nevermined API is reachable. |

Send both `Content-Type: application/json` and `Accept: application/json, text/event-stream`. `initialize` reports the server as `nevermined-commerce`.

### Environments

The server runs on two hostnames per environment. They serve the **same tools** and differ only in **when** a request without a credential is challenged.

| Environment | Server URL | Behaviour |
| --- | --- | --- |
| **Live** | `https://mcp.live.nevermined.app/mcp` | Real merchants, real money. Discovery and free tools answer with no credential; a paid tool returns `401` + challenge. |
| **Sandbox** | `https://mcp.sandbox.nevermined.app/mcp` | Testnet merchants, testnet funds — the place for a first run. |
| **Live (challenge-on-connect)** | `https://mcp.api.live.nevermined.app/mcp` | Challenges `401` on the very first request. For hosts that only look for auth when they first connect (e.g. LangSmith Fleet). |
| **Sandbox (challenge-on-connect)** | `https://mcp.api.sandbox.nevermined.app/mcp` | As above, on sandbox. |

Use the `mcp.<env>` host unless your client only starts OAuth when the server challenges it on connect — then use `mcp.api.<env>`. See [What happens without a credential](/products/catalog/mcp#what-happens-without-a-credential).

## Authentication

Two ways to authenticate, one server. The credential — key or grant — is forwarded to the Nevermined API **per request**, never stored, never logged, and never sent to the merchant.

- **API key** — put your Nevermined key on `Authorization: Bearer <key>`. Works on any host that can send headers. This is the path the [quickstart](/products/catalog/mcp#quickstart) uses.
- **OAuth** (`commerce` scope) — connect with **no** header. The server is an OAuth 2.0 protected resource; when it needs a credential it answers `401` with a `WWW-Authenticate` challenge pointing at `/.well-known/oauth-protected-resource/mcp`. Your host runs the flow, you approve a spending cap once, and it retries with the grant. The grant spends only from the Delegation you approved, through the Router. See [Auth & transport](/products/catalog/mcp#auth-&-transport) for the full OAuth walkthrough and which hosts can be granted `commerce`.

### Free vs paid tools

Discovery is **free** — no credential. Everything else needs a credential, either your API key or an OAuth `commerce` grant. "Paid" here means *needs a credential*; of those, only `pay_service` and `route_by_intent` (with `autoPay: true`) move money — the rest read your account or price a call and charge nothing.

Every tool declares its requirement in its listing (`securitySchemes`: `noauth` on the free tools, `oauth2` with the `commerce` scope on the rest), so a host that reads tool metadata knows which tools need linking before it calls one.

## The tool surface

| Tool | Auth | Charges | What it does |
| --- | --- | --- | --- |
| [`list_categories`](/api-reference/catalog-mcp/discovery#list_categories) | free | — | Catalog categories and sub-categories, with a count each. |
| [`search_services`](/api-reference/catalog-mcp/discovery#search_services) | free | — | Search listings, hybrid (semantic + keyword) ranking, most relevant first. |
| [`get_service`](/api-reference/catalog-mcp/discovery#get_service) | free | — | One service by `slug` — metadata and a `requestShape` naming each callable endpoint and its `pay_service` arguments. |
| [`quote_service`](/api-reference/catalog-mcp/payments#quote_service) | key / grant | nothing | Price one call before paying it — live, fee-inclusive total, rail and network. Reaches the service unpaid. |
| [`pay_service`](/api-reference/catalog-mcp/payments#pay_service) | key / grant | **real funds** | Pay for a service and return the vendor's response. |
| [`route_by_intent`](/api-reference/catalog-mcp/payments#route_by_intent) | key / grant | **real funds if `autoPay`** | Describe a need; get the single best payable service plus a ranked shortlist, and optionally pay it. |
| [`setup_delegation`](/api-reference/catalog-mcp/payments#setup_delegation) | key / grant | nothing | Start the delegation ceremony — returns one URL a human opens to authorise a spending cap. |
| [`get_payment_result`](/api-reference/catalog-mcp/payments#get_payment_result) | key / grant | nothing | Read a paid call's result by `paymentId` — for a `pending` call, or a response you lost. |
| [`list_payments`](/api-reference/catalog-mcp/ledger#list_payments) | key / grant | nothing | Your Router payments (unified ledger, newest first). |
| [`payment_summary`](/api-reference/catalog-mcp/ledger#payment_summary) | key / grant | nothing | Count of payments over a period, plus a daily time series. |
| [`get_budget`](/api-reference/catalog-mcp/ledger#get_budget) | key / grant | nothing | The spending budget `pay_service` draws on — cap, spent, remaining, expiry. |
| [`wallet_balance`](/api-reference/catalog-mcp/ledger#wallet_balance) | key / grant | nothing | What your funding wallet holds, per network. |

## Result and error conventions

These hold across every tool; each tool's page notes only what it adds.

- **One JSON object per call.** Each tool returns a single JSON object as the MCP text content. The examples on these pages are that object.
- **Refusals are legible results, not exceptions.** A tool that cannot proceed returns an object carrying an `error` (and often a `code` and `retryable`), so an agent can branch on it. The payment tools' refusals are tabulated on the [Payments](/api-reference/catalog-mcp/payments) page.
- **Missing or rejected credential → `401`.** A paid tool called with no credential, or one Nevermined refused (`error="invalid_token"`), returns HTTP `401` with a `WWW-Authenticate` challenge. An OAuth-capable host handles this itself; a headers-only host must set its API key. A host that links per tool gets the same challenge in-band under `_meta["mcp/www_authenticate"]`.
- **Money is in cents.** Budget figures are cents: `capCents` is whole cents; `spentCents` and `remainingCents` can carry up to four decimals, because the budget is charged per call at 1/10,000 of a cent. The routing fee is included in what the budget records — never re-derive a figure by summing your own calls. Payment *amounts* in [`list_payments`](/api-reference/catalog-mcp/ledger#list_payments) are in the asset's smallest unit (see `assetDecimals`), not cents.
- **Error codes.** Router refusals carry `BCK.ROUTER.*` codes documented under [Router guardrails](/products/catalog/router/guardrails#every-error-code); OAuth refusals carry `BCK.OAUTH.*` codes. The full catalogue is the [API error reference](/development-guide/api-errors/overview).
