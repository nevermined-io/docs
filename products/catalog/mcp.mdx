The **Catalog MCP** (also called the Commerce MCP) is a hosted [MCP](https://modelcontextprotocol.io) server that drops the Nevermined Catalog and Router straight into the tools an AI assistant already has. Point any MCP host — Claude, ChatGPT, Cursor, a generic MCP client — at it, and your agent can **discover** paid services in the [Nevermined Catalog](/products/catalog/overview) and **pay** for them through the [Router](/products/catalog/router/overview), all from a budget you cap. No code, no per-vendor signup: the server holds no funds and stores no state, and every payment draws on the caller's own spend-capped Delegation.

<Note>
This is the **buyer** side, packaged as MCP tools. If you instead want to put a paywall on *your own* MCP server so its tools get paid, that's the seller side — see [MCP Integration](/integrations/mcp). The [Docs MCP](/mcp/docs-mcp/overview) is a third, unrelated server that streams this documentation into your IDE.
</Note>

<Info>
**The full guide lives in the MCP section: [Catalog MCP Overview](/mcp/catalog-mcp/overview).** It covers how to import the server into any harness, Claude or ChatGPT; authentication; the walkthrough quickstart; and the complete tool surface — with a reference page per tool. This page is the short introduction and the video.
</Info>

## How it fits: discover, then pay

<CardGroup cols={2}>
  <Card title="Discover" icon="magnifying-glass">
    [`list_categories`](/mcp/catalog-mcp/list-categories), [`search_services`](/mcp/catalog-mcp/search-services), and [`get_service`](/mcp/catalog-mcp/get-service) read the [Catalog](/products/catalog/discover) — public, no key. Your agent finds a service and reads its protocol, endpoint, and price.
  </Card>
  <Card title="Pay" icon="route">
    [`pay_service`](/mcp/catalog-mcp/pay-service) hands the call to the [Router](/products/catalog/router/overview), which reads the merchant's `402`, pays it from your Delegation, enforces the cap, and relays the vendor's response. [`route_by_intent`](/mcp/catalog-mcp/route-by-intent) does both steps in one call.
  </Card>
</CardGroup>

Your agent never holds a private key, never learns a payment protocol, and never needs an account with the service it just paid. The Router, not the agent, speaks each rail — see [How the Router works](/products/catalog/router/how-it-works).

## Not this MCP

Nevermined ships three MCP servers. Make sure you want this one:

| MCP | Side | What it's for |
| --- | --- | --- |
| **Catalog MCP** (this page) | Buyer | Your agent discovers & pays for Catalog services. You provide just an API key and a funded budget. |
| [MCP Integration](/integrations/mcp) | Seller | Put a paywall on *your own* MCP server with the Payments Library (`withPaywall`), so your tools get paid. |
| [Docs MCP](/mcp/docs-mcp/overview) | — | Streams the Nevermined **documentation** into your IDE so an assistant can vibe-code an integration. It sells nothing. |
