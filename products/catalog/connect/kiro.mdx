Kiro can browse the [Nevermined Catalog](/products/catalog/overview) and pay for services as it works, without you handing over an API key. You add one server, approve a single spending cap, and Kiro does the rest. This is the per-host walkthrough; for the concept and the other assistants, see [Using the Catalog from your web assistant](/products/catalog/from-your-web-assistant).

## Before you connect

<Steps>
  <Step title="A Nevermined account">
    Free, at [nevermined.app](https://nevermined.app). You never share an API key with Kiro — the consent cap *is* the credential.
  </Step>
  <Step title="A funded wallet">
    A paid call draws on a **spending cap** you approve during connect — a [commerce grant](/mcp/catalog-mcp/overview#auth-&-transport): a capped, revocable budget funded from your own wallet, not a key. Fund that wallet first with the asset the service settles in — see [Fund your wallet](/products/catalog/router/quickstart#3-fund-your-wallet). You approve the cap itself in [Approve the spending cap](#approve-the-spending-cap).
  </Step>
</Steps>

<Note>
Start on **sandbox**, where you use testnet funds and nothing costs real money, before you point Kiro at **live**.
</Note>

## Add the Catalog to Kiro

<Steps>
  <Step title="Add the server to your Kiro MCP config">
    Add a remote MCP server to Kiro's MCP config — `.kiro/settings/mcp.json` in your workspace, or `~/.kiro/settings/mcp.json` for every workspace — pointing at the environment you want. Set `oauth.clientId` to `kiro` and omit `clientSecret` — the Kiro IDE supports public clients only, so there is no secret to paste:

    ```json
    {
      "mcpServers": {
        "nevermined": {
          "url": "https://mcp.api.sandbox.nevermined.app/mcp",
          "oauth": {
            "clientId": "kiro"
          }
        }
      }
    }
    ```

    For **live**, use `https://mcp.api.live.nevermined.app/mcp`. Use the `mcp.api.<env>` host (not `mcp.<env>`): Kiro only starts OAuth when it connects to a server that challenges, and this host challenges on the first request. You don't need `redirectUri` — Kiro's default loopback callback (path `/oauth/callback`, on a random port) is already registered for the `kiro` client, and Nevermined matches it on any port.
  </Step>
  <Step title="Sign in">
    Kiro opens Nevermined's consent page in your browser when it connects to the server — see [Approve the spending cap](#approve-the-spending-cap).
  </Step>
</Steps>

## Approve the spending cap

Kiro opens Nevermined's consent page when it first connects to the server. It is the one place a human is required.

<Steps>
  <Step title="Check who and where">
    The page shows the **Sandbox / Live** badge and **who is asking**. On **live**, the cap is real money.
  </Step>
  <Step title="Set the cap and validity">
    Set the **spending cap** (USDC or EURC) and how long the grant is **valid for**, then **Grant access**.
  </Step>
</Steps>

That approval is a **commerce grant**: it spends only from the budget you just approved, only through the [Router](/products/catalog/router/overview), and you can revoke it any time. Nevermined's routing fee comes out of the same cap, and the grant can also read your payment history and wallet balance — [the cap bounds what it can spend, not what it can see](/mcp/catalog-mcp/overview#what-the-consent-page-asks).

## Make your first paid call

Once you've connected and approved the cap, name the connector so Kiro reaches for it rather than answering from memory.

<Steps>
  <Step title="Browse the catalog">
    Ask *"list the Nevermined catalog categories through the Nevermined connector"* to see what's available.
  </Step>
  <Step title="Ask it to buy">
    *"Buy the service with slug `<slug>` through the Nevermined connector and show me the response."* The paid call draws on the cap you approved and returns the merchant's response.
  </Step>
</Steps>

<Tip>
If Kiro answers without paying, it answered from its own knowledge — name the connector and ask for live data. More on phrasing: [Catalog MCP tips](/mcp/catalog-mcp/overview#connect-from-your-assistant).
</Tip>

## Disconnect

- **Revoke the budget (Nevermined side).** Open [Connections](https://nevermined.app/connections) and disconnect Kiro. The credential stops working on its next call; discovery still works.
- **Remove the connector (Kiro side).** Remove the `nevermined` entry from the `mcpServers` block in your `mcp.json`, or set `"disabled": true` on it to switch it off without deleting it.

To spend again — after you disconnect, or after a cap is used up — re-run the connect step and approve a **new** cap. A budget is never widened or extended in place.
