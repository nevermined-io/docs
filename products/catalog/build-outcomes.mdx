Most integrations start the wrong way round: you pick a search API, a scraper, and an LLM, sign up for each, wire in three keys, and glue them together — before you've solved anything. The Catalog flips it. You describe the **outcome** you want, attach a **budget**, and your agent uses the [Nevermined Catalog](/products/catalog/overview) to discover the building-block services and chain them into a solution. No per-vendor signup, no wiring — each service settles per call against a budget you cap.

<Note>
This is the composition mindset: an AI service is a **building block**, not a destination. A real problem — *"tell me everything the web knows about this person"* — is several blocks (search, scrape, capture, synthesis) the Catalog proposes and the [Router](/products/catalog/router/overview) pays for, one call at a time.
</Note>

## How an outcome comes together

<Steps>
  <Step title="State the problem and a budget">
    One prompt: the result you want, and the most you'll spend getting it. The budget is the guardrail — the agent works *within* it.
  </Step>
  <Step title="The agent searches the Catalog (free)">
    Discovery needs no key and costs nothing. The agent breaks the problem into blocks and searches for each — *search*, *scrape*, *synthesis* — reading real slugs, prices, and health.
  </Step>
  <Step title="The Catalog proposes a chain">
    Candidate services per block, ranked and priced. This is the "solution" — a concrete set of services that, chained, produce the outcome. You can see it before a cent is spent.
  </Step>
  <Step title="Approve a cap once, and it runs">
    Approve a spending cap, and the Router pays each call within it. Connecting and paying is covered in [Using the Catalog from your web assistant](/products/catalog/from-your-web-assistant) and [from a harness](/products/catalog/from-a-harness).
  </Step>
</Steps>

Everything up to the proposal is **free and reproducible right now** — that's what this page's prompts and queries exercise. Turning a proposal into a paid run needs a connected harness and a funded budget.

## See what the Catalog proposes

The discovery step is **public and free** — no key, no budget, no spend. Run these against production and you'll see the same services a harness would propose. All four are verified working as written.

**Browse the whole catalog**, see the real shape of a listing (`.total` is the live count):

```bash
curl -s https://nevermined.app/catalog/ai-catalog.json | jq '{total, first: .services[0]}'
```

**List the categories** through the Catalog MCP server (Streamable HTTP, stateless — one POST, no key):

```bash
curl -s -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -X POST https://mcp.live.nevermined.app/mcp \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_categories","arguments":{}}}' \
  | jq -r '.result.content[0].text' | jq .
```

**Find the building blocks for an outcome** — one search per block, top 3 hits each:

```bash
for q in "web search" scrape screenshot chat; do
  curl -s -H "Content-Type: application/json" \
       -H "Accept: application/json, text/event-stream" \
       -X POST https://mcp.live.nevermined.app/mcp \
       -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",\"params\":{\"name\":\"search_services\",\"arguments\":{\"query\":\"$q\"}}}" \
    | jq -r '.result.content[0].text' \
    | jq --arg q "$q" '{query:$q, total, top:[.services[0:3][]|{slug,title,protocol,priceLabel}]}'
done
```

**Read one service's callable shape** — endpoints, method, and the exact arguments to pay it:

```bash
curl -s -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -X POST https://mcp.live.nevermined.app/mcp \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_service","arguments":{"slug":"orth-seltz"}}}' \
  | jq -r '.result.content[0].text' | jq '.requestShape'
```

<Tip>
**Search is a whole-substring match on a service's title or short description, and it is order-sensitive** — so query with single words or a known substring. `web search` finds services and `search web` finds none; `weather` finds four and `weather forecast` finds none. Narrow with the `category` and `tag` filters rather than by stacking words. The results also carry each service's `healthStatus` (`operational` / `unverified`) and recent uptime, so an agent can prefer a service that's actually up.
</Tip>
