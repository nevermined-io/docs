A human browses the Catalog in the app. An agent reads its **public, unauthenticated** feed, or searches it through the Catalog MCP server. All three surface the same curated set of Router-payable services.

## Browse in the app

Open [nevermined.app/catalog](https://nevermined.app/catalog/) to explore listings visually:

- **Categories** — filter by top-level category and sub-category (Search & Research, Crypto & Blockchain, AI & Media, and more).
- **Search** — free-text over a service's title and description.
- **Service detail** — each listing has a page with its description, protocol, indicative price, callable endpoints, tags, and links to the provider's homepage and docs.

The app is a browsing surface. To actually *buy*, an agent drives the [Router](/products/catalog/router/quickstart) — the same directory, read programmatically.

## Read the feed

Every listed service is in one public JSON document, **[ai-catalog.json](https://nevermined.app/catalog/ai-catalog.json)**. It's unauthenticated and cached for five minutes, so send no `Authorization` header. Fetch it once and filter on your side:

```bash
curl -s https://nevermined.app/catalog/ai-catalog.json -o ai-catalog.json
jq '.total' ai-catalog.json
```

<Note>
**`/api/v1/catalog/services` and `/api/v1/catalog/categories` aren't a public integration.** They return `403` to outside callers, by design. Read the feed instead, or use the [Catalog MCP](#search-server-side-with-the-catalog-mcp) when you want the search done for you.
</Note>

The feed lists the **live** Catalog, and its services are live-only for payment: they settle on mainnet and a sandbox deployment funds testnets only, so paying one from sandbox fails with `400 BCK.ROUTER.0001` (see [an agent buying on its own](/products/catalog/router/agent-autonomy)). The one exception is the pair of free testnet test merchants the sandbox Catalog carries for rehearsal — see [the Commerce MCP page](/products/catalog/mcp#1-connect-your-host).

### Filter it

The feed has no query parameters: it's the whole Catalog, so every filter runs on your side. These all work as written against the file you just saved.

**By category and protocol:**

```bash
jq '[.services[] | select(.category == "Search & Research" and .protocol == "x402")
     | {slug, title, priceLabel}]' ai-catalog.json
```

**By free text** over title and description, case-insensitive:

```bash
jq --arg q "crypto" '[.services[]
     | select((.title + " " + .description) | ascii_downcase | contains($q | ascii_downcase))
     | {slug, title, protocol, priceLabel}]' ai-catalog.json
```

**The categories in use**, with a count and the sub-categories under each:

```bash
jq '.services | group_by(.category)
     | map({category: .[0].category, count: length, subCategories: (map(.subCategory // empty) | unique)})' ai-catalog.json
```

**One service by slug**, with the path to send for each endpoint:

```bash
jq '.services[] | select(.slug == "superhighway")
     | {slug, protocol, invokeUrl, endpoints: [.endpoints[] | {method, path: (.invokePath // .path), priceLabel}]}' ai-catalog.json
```

Category names are matched verbatim — `"Search & Research"`, not `"Search"` — and a misspelt one returns an empty list, not an error. Take them from the categories recipe rather than from memory.

The fields you'll actually use on each service:

| Field | Use |
| --- | --- |
| `slug` | Stable, case-sensitive id — how you address the service through the Router |
| `protocol` | `x402` or `mpp` — payable through the Router |
| `category` / `subCategory` | Curated category and its granular label (`subCategory` is absent when there is none) |
| `priceLabel` | Human string like `"$0.001"` — **indicative only**; the wire price governs |
| `network` / `networks` | Display names (`"Base"`, `"Tempo"`), not chain ids |
| `endpoints[]` | `{ path, method, description, priceLabel }`; some also carry `invokePath`, `requestExample` and `responseFields` |
| `invokeUrl` | The service's Router URL, `…/api/v1/router/svc/<slug>` |
| `invoke` | A ready-made Router call: method, URL and the `X-Router-*` headers to send |

<Warning>
**The feed carries no merchant URL, on purpose.** You pay a listed service **by its slug**: the Router resolves the merchant's host server-side and refuses a raw-URL payment to it with `409 BCK.ROUTER.0014`. For an endpoint, send its `invokePath` when present — even when it's `""`, which means "append nothing" — and its `path` otherwise. In code that's `invokePath ?? path`, not `||`: turning `""` back into the path double-stacks it, and the call 404s after the charge.
</Warning>

## Search server-side with the Catalog MCP

The [Catalog MCP server](/products/catalog/mcp) does the search for you. Its `search_services`, `get_service` and `list_categories` tools are free and need no key. One stateless POST per call:

```bash
curl -s -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -X POST https://mcp.live.nevermined.app/mcp \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search_services","arguments":{"query":"crypto","protocol":"x402"}}}' \
  | jq -r '.result.content[0].text' | jq .
```

Always send a `query`, and read the result as plain JSON rather than a fixed shape — search is moving to semantic ranking with a new result format (see [Run a discovery call](/products/catalog/mcp#3-run-a-discovery-call)). Don't page through it: to see the whole Catalog, use the feed. More worked calls, including `get_service`'s `requestShape`, are in [Build Outcomes](/products/catalog/build-outcomes#see-what-the-catalog-proposes).

## For crawlers and registries

- **[`/.well-known/ard.json`](https://nevermined.app/.well-known/ard.json)** — the [Agentic Resource Discovery](/integrate/authentication/for-agents) host document: one entry per service with its Router pay-through target and health status (`nvm:catalog.healthStatus`). Its list key is `entries`, not `services`.
- **[`/catalog/llms.txt`](https://nevermined.app/catalog/llms.txt)** — the plain-text entry point for an agent landing on the Catalog cold.

<Tip>
The full machine-facing discovery contract — the feed's fields, the slug-addressing rule, and more filter recipes — ships in the **[Router AI coding skill](/development-guide/build-using-nvm-skill)** (`nevermined-router`), so your assistant already knows how to walk the Catalog.
</Tip>

## What "listed" means

The Catalog only lists services the Router can actually pay — those that price each request on the wire (**x402** and **MPP**). Services that bill out of band aren't listed, so a browsing agent is never handed one it can't buy. More on the Catalog's contents in [AI Services](/products/catalog/ai-services#what-gets-listed).

## From discovery to a paid call

Once you've picked a service, buying it is the Router flow:

<Steps>
  <Step title="Read its slug and endpoint">
    Straight off the feed entry: the `slug`, plus the endpoint's `invokePath ?? path`. You don't need to know x402 from MPP — the Router probes the service and detects the protocol from its `402`.
  </Step>
  <Step title="Get an API key, a Delegation, and funds">
    A one-time setup — see the [Router quickstart](/products/catalog/router/quickstart).
  </Step>
  <Step title="Route the call">
    Hand the Router the slug and the request. It pays the `402` from your wallet, enforces your cap, and relays the answer.
  </Step>
</Steps>
