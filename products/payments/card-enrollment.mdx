## Overview

Before an agent can charge a payment card, the card must be enrolled in Nevermined. Enrollment tokenizes the card data (Nevermined never stores raw card numbers) and registers the card with the provider so future delegations can authorize off-session charges.

The [Nevermined App](https://nevermined.app) has one card form, and it captures every card through VGS. You don't choose a provider to pay a Stripe-priced or a Braintree-priced plan: the plan's `fiatPaymentProvider` metadata picks the provider that charges the card, at charge time.

- **Stripe-priced plans** and **Braintree-priced plans** are paid with a card enrolled through the credit/debit card form.
- **Visa Trusted Agent plans** require a Visa Agentic Token (enrolled through the Visa Agentic option on the same form, where it is offered).

## Enrollment Paths

<Tabs>
  <Tab title="Visa">
    ### Visa Enrollment

    Visa cards are enrolled as **Visa Agentic Tokens** through the VGS Credential Management Platform (CMP). Card capture happens in a VGS Collect iframe in the Nevermined webapp, so the raw PAN never reaches Nevermined infrastructure.

    <Steps>
      <Step title="Capture card data">
        Enter your card details in the VGS Collect iframe rendered by the webapp. VGS Collect's `form.createCard()` posts the tokenized card directly to CMP and returns a CMP `cardId` (`CRD…`) to the browser. The PAN and CVC never transit the Nevermined backend.
      </Step>
      <Step title="Mint the Agentic Token">
        The browser sends only the `cardId` (plus BIN-derived `last4`, `brand`, and `expMonth`/`expYear`) to `POST /api/v1/delegation/enroll-visa`. The backend calls VGS Agentic `POST /cards/{cardId}/agentic-tokens` to mint the long-lived Agentic Token (`vat_…`) and persists it as the card's `providerPaymentMethodId`.
      </Step>
      <Step title="Create a delegation">
        After enrollment, create a [spending delegation](/products/payments/mandates). Each Visa delegation requires a one-time WebAuthn/passkey device-binding ceremony embedded by Visa VTS — see the Visa tab on the [Delegations](/products/payments/mandates) page.
      </Step>
    </Steps>

    #### Visa Card Lifecycle

    ```
    PAN captured in VGS Collect iframe
      |
      |-> CMP card created (cardId)
      |
      |-> Backend enrolls Agentic Token (vat_…)
      |
      |-> PaymentMethodEntity persisted (provider='visa')
      |
      |-> Active -> Delegations can be created
            |
            |-> Removed (card and all delegations revoked)
    ```

    <Note>
      VGS Agentic Tokens are keyed on PAN globally. Re-enrolling the same physical card always resolves to the same `cardId`/`tokenId`. If the card is already enrolled under a different Nevermined account, enrollment returns `BCK.VISA.0018` (HTTP 409).
    </Note>

    <Note>
      No passkey is required at enrollment. The WebAuthn/passkey ceremony happens once per delegation, not once per card.
    </Note>

    <Note>
      Visa enrollment is only reachable from the Nevermined webapp. The `/api/v1/delegation/enroll-visa` endpoint expects a CMP `cardId` produced by VGS Collect in the browser; it cannot be driven from a server-side SDK or curl call.
    </Note>
  </Tab>
  <Tab title="Credit/debit card">
    ### Credit/debit card enrollment

    A card for a Stripe-priced or a Braintree-priced plan is enrolled through the webapp's "Credit/debit card" form. The card is captured in a VGS Collect iframe and vaulted at VGS, not at Stripe or Braintree: the plan you pay picks the provider that charges it, at charge time. This is a single-step flow with no passkey requirement.

    <Steps>
      <Step title="Enter card details">
        Enter your card number, expiry, and CVC into the VGS Collect iframe. VGS Collect creates the card directly at VGS and returns a card ID (`CRD…`) to the browser. The PAN and CVC never transit the Nevermined backend.
      </Step>
      <Step title="Enroll the card">
        The webapp posts the card ID to `POST /api/v1/delegation/enroll`. The API provisions a network token for the card and records it under your account.
      </Step>
      <Step title="Create a delegation">
        After enrollment, create a [spending delegation](/products/payments/mandates) to define how agents can charge this card.
      </Step>
    </Steps>

    #### Card Lifecycle

    ```
    PAN captured in VGS Collect iframe
      |
      |-> VGS card created (cardId)
      |
      |-> Backend provisions a network token and records the card
      |
      |-> Active -> Delegations can be created
            |
            |-> Removed (card and all delegations revoked)
    ```

    <Note>
      A Braintree-priced plan can only be charged when its seller has a Braintree merchant account in the plan's currency. See [Braintree onboarding](/products/payments/braintree-onboarding) for the seller-side per-currency requirements.
    </Note>
  </Tab>
</Tabs>

## Card Properties

All enrolled cards share these core properties:

| Property | Description |
|---|---|
| `id` | Unique payment-method identifier (UUID) |
| `userId` | Owner of the card |
| `provider` | `visa`, `vgs` (a card enrolled through the credit/debit card form), or `braintree` / `stripe` (a card enrolled outside that form) |
| `providerPaymentMethodId` | Provider-side card reference. Visa: `vat_…` (Agentic Token). VGS: the VGS card ID (`CRD…`). Braintree: `paymentMethodToken`. Stripe: `pm_…`. |
| `last4` | Last 4 digits of the card number (for display) |
| `brand` | Card brand (`visa`, `mastercard`, …) |
| `alias` | User-friendly name (e.g., "Work Visa", "Dev Card") |
| `status` | `active` or `inactive` |

## Managing Cards

### Via the Nevermined App

The [Nevermined App](https://nevermined.app) provides a visual interface for managing your enrolled cards. All your cards appear in one list:

- View all enrolled cards with their status
- See active delegations per card with remaining budget
- View transaction history for each card
- Deactivate or remove cards

### Via the API

The payment-methods endpoint is heterogeneous: it lists enrolled cards across all providers plus, when the user has a smart account configured, the ERC-4337 wallet entry that backs crypto delegations. Filter by `provider` to narrow to a single shape: a card enrolled through the credit/debit card form is `provider=vgs`, not `stripe` or `braintree`.

| Endpoint | Method | Description |
|---|---|---|
| `/api/v1/payment-methods` | `GET` | List enrolled payment methods (cards + ERC-4337 wallet) |
| `/api/v1/payment-methods/{id}` | `PATCH` | Update alias or allowed API keys |
| `/api/v1/payment-methods/{id}` | `DELETE` | Remove card and revoke all delegations on it |
| `/api/v1/delegation/{id}/transactions` | `GET` | Per-delegation transaction history |

## Choosing a Provider

| | Visa | Credit/debit card |
|---|---|---|
| **Enrollment complexity** | VGS Collect capture, no passkey at enrolment | VGS Collect capture, no passkey at enrolment |
| **Per-delegation auth** | WebAuthn/passkey device binding (browser-only) | API credentials only |
| **Best for** | Visa Trusted Agent Protocol plans, high-security agent payments | Stripe-priced and Braintree-priced plans, quick setup, developer testing, broader card support |
| **Settlement** | Stripe Connect against the seller's connected account | Set by the plan: Stripe PaymentIntents directly, or a Braintree sale with the card's network token on the seller's OAuth-connected merchant account |

Both support the same spending controls (spending limits, usage limits, expiration) and API key linking. The plan's `fiatPaymentProvider` metadata decides how a credit/debit card settles, so the same card can pay a Stripe-priced and a Braintree-priced plan. A Visa Trusted Agent plan can only be paid by a Visa Agentic Token.

To see which provider a plan settles on, read it from the plan. `resolveNetwork()` / `resolve_network()` returns the plan's card provider (`stripe` or `braintree`), or `undefined`/`None` if the plan sets no `fiatPaymentProvider`:

<Tabs>
  <Tab title="TypeScript">
    ```typescript
    import { resolveNetwork } from '@nevermined-io/payments'

    const provider = await resolveNetwork(payments, planId)
    // 'stripe' | 'braintree' for a fiat plan that sets fiatPaymentProvider; otherwise undefined
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from payments_py.x402.resolve_scheme import resolve_network

    provider = resolve_network(payments, plan_id)
    # 'stripe' | 'braintree' for a fiat plan that sets fiatPaymentProvider; otherwise None
    ```
  </Tab>
</Tabs>

For `stripe` or `braintree`, enroll through the credit/debit card form, then [create a delegation](/products/payments/mandates) from the enrolled card. If `resolveNetwork` returns nothing, the plan sets no `fiatPaymentProvider`: it is a crypto plan, or a fiat plan registered without one.
