Clients below 1.91 keep the old header and payment shape. Pending 202 responses have no upstream status yet. - **POST /api/v1/router/subscription/quote can price a request from the merchant’s live answer: credits is then the exact cost of that request, tariffVersion is absent, and paymentRequired and upstreamStatus say what the merchant answered. - **Where credits follow each call’s live price, the catalog reads publish estimatedCreditsPerCall, and an endpoint no tariff covers carries only that field. Older pins read such an endpoint as they always did, as not payable with credits; on the others estimatedCreditsPerCall is an addition, and creditsPerCall stays the tariff’s figure, which no longer prices the call. On such a deployment every pin loses the service-level subscription, since no default prices a call, and subscription on an endpoint whose last price is above the per-call limit. Since 1.94 every call follows its live price: no tariff sets creditsPerCall, tariffVersion or the service-level subscription on any pin, so pins below 1.91 read no endpoint as payable with credits on these routes and the credits index lists no service for them; paying with credits is unaffected.** (`response`)

## 1.43

_Changes relative to `1.34`:_

- **BREAKING (shipped as a MINOR — see note): POST /organizations/:orgId/billing/upgrade no longer applies the tier inline. It now returns upgraded:false with requiresPayment:true and a clientSecret for a standalone PaymentIntent; only the payment_intent.succeeded webhook grants the tier. A client resolved below 1.43 CANNOT render the PaymentElement, so the handler REFUSES it up front with BCK.BILLING.0031 (an error, before any Stripe change) rather than returning a half-usable success — so this gate never actually reshapes a success response for an old client (it only ever sees 1.43+ responses); it is retained to register the 1.43 version boundary and as defence-in-depth. Released as 1.43 rather than 2.0.0 deliberately: the API version is the monorepo-wide MAJOR.MINOR, and a major bump would force every client on every endpoint to re-evaluate its pin for one endpoint whose old behaviour was itself a money bug (it granted paid tiers without payment). The break is now explicit (a 400 that names the required version), not a silent shape change, which is why a minor + the 0031 refusal is the deliberate choice.** (`response`)
  - `POST /api/v1/organizations/:orgId/billing/upgrade`
